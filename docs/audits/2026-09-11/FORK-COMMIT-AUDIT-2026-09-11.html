Executive verdict

Keep the architecture and most repairs. Fix what the monitor fails to tell you.

The fork is in better shape than it was two weeks ago. The PostGIS collector is fresh, fast at its present size, transactionally safe, and correctly distinguishes unknown status. The September 8 repair batch fixed real request, map, CSV and caching defects. I found no reason to roll that batch back.

The main regression pattern is subtler. The app often looks successful while withholding important context. An open Voi page stops discovering new snapshots, smooth lines connect missing collection intervals, and the normal UI cannot select months of retained history. The new non-defect policy series has the same failure shape. If one of many daily requests fails, the line disappears.

Findings that affect your workflow

"Confirmed" means the behavior is present in the current source or production. "Intent mismatch" means the code works as written, but the restriction conflicts with a sole-user monitoring fork. Findings are ordered by practical impact.

1

The monitor can be stale or incomplete while looking current and continuous

Confirmed · fix first

VoiVehicleHistory loads /index.json only when the page mounts. Leave the tab open and it never discovers later ten-minute captures. The API already has a freshness-aware /health endpoint. The UI does not use it, and the "latest measurement" summary does not show a capture time or age.

The second half is more serious: a real outage currently looks like ordinary continuous data. Production has no snapshots at 15:00 and 15:10 UTC on 11 September. The next stored boundary is 15:20. The API returns only existing snapshots, and Recharts draws one monotone line through consecutive rows, so the graph bridges the 30-minute hole.

Production evidence. API connection timeouts appeared from 15:17 to 15:21. The collector then stored the 15:20 boundary. The latest sampled collector deployment otherwise had 36 successful stores in 36 starts. This is a real, bounded outage. The finding does not rest on code alone.

Recommendation. Refresh the index after each ten-minute boundary and provide a manual refresh. Show the displayed capture time and age. Compute expected boundaries and insert null rows or break the line for missing captures. Show a compact completeness count such as "1006 of 1008 expected". A small backfill command is useful, but visible gaps are still necessary because backfill can also fail.

2

The app stores months of history but the viewer exposes seven days

Intent mismatch · fix first

The archive is deliberately retained until a 5 GB volume fills, about nine months at the documented growth rate. Yet the timeline calls listVoiSnapshots() without dates, so the API's seven-day default defines everything the slider can see. The area chart offers 1, 7, and 31 days. The API rejects any window over 31 days and caps the index at 4,500 entries.

This resembles the CSV restriction you reverted: the defensive limit is internally consistent, but it blocks the reason the data exists. Older snapshots remain reachable only by manually issuing separate API or GIS queries.

Source evidence. VoiVehicleHistory.tsx:247 to 271, voi_availability.py:14 to 55, and voi_api.py:57 to 72. The deployed index held 508 snapshots over roughly four days when checked. This limitation becomes visible after the first week of ten-minute collection.

Recommendation. Add explicit date navigation to the timeline and area chart. Paginate or window the index so long history is fetched on demand. Keep sensible per-frame and polygon limits. Remove the blanket 31-day analytical ceiling unless measured production performance justifies it.

3

The new non-defect policy line is an all-or-nothing fan-out

Confirmed · next

The intent is right. Compare each provider's ordinary availability series with vehicles whose is_non_operational flag is false. The implementation asks the raw park_events endpoint once for every chart day, four requests at a time. The default 30-day view adds about 30 raw requests. A 12-month selection adds about 365.

Promise.all rejects the entire set when one day fails. The chart catches that only in the console, retains the ordinary line, and leaves the non-defect data empty. To the user, the feature silently vanishes. The requested daily instant is also created with browser-local moment(), unlike the rest of the recent statistics work that pins reporting to Europe/Amsterdam.

Source evidence. operationalVehicleStats.ts:63 to 90, BeschikbareVoertuigenChart.tsx:128 to 173, and availableVehiclesChartUtils.ts:23 to 37. The existing test expects UTC because Jest runs in UTC. It does not exercise Amsterdam versus another browser timezone.

Recommendation. Prefer one backend aggregate request. Short of that, return partial daily results, show failed dates, retry only failures, and set the reporting timezone explicitly. Do not let a failure of this secondary series look like success.

4

The trip-length chart still carries unmeasured safety limits

Likely mismatch · next

The September 8 repair correctly added cancellation, visible HTTP errors, response validation and stale-result handling. It also hard-coded a 31-day period, 10 MB response and 50,000-trip ceiling. The surrounding period control still offers 90 days, 12 months, this year and last year, so this chart alone errors for otherwise valid selections.

The earlier audit said the endpoint's practical contract had not been established. That makes these numbers defensive guesses rather than evidence-based limits. Raw trips can be large. Deleting every safeguard without a replacement would move the failure to browser memory.

Source evidence. src/api/trips.js:6 to 60 and the broader presets at Filterbar.tsx:228 to 243.

Recommendation. For this Voi-focused fork, first measure the region and month shapes you request. Then use a server histogram or pagination. Until that exists, make any necessary limit match the UI and explain it before the request. Do not fail one chart after selection.

5

The main Voi guide describes a system that no longer exists

Confirmed · next

docs/VOI-VEHICLE-MONITOR.md still tells the operator that GitHub Actions collects hourly, publishes a voi-vehicle-data branch, stores 90-day artifacts, and can be run manually as a workflow. Collection now runs every ten minutes in Railway and stores in PostGIS. The old branch is not updated.

The accurate document is .railway/README.md. This was already identified on 6 September but survived the migration. For a one-person fork, duplicate documentation is worse than sparse documentation because the likely reader is future-you during an incident.

Recommendation. Replace the old guide with a short redirect to the Railway runbook or rewrite it as the user-facing overview, with the runbook as the operational detail.

6

CI was restored for pull requests, not for the way this fork usually deploys

Workflow gap · next

.github/workflows/check.yml runs the test suite, scoped typecheck and production build for pull requests and manual dispatches only. The first-parent history shows frequent direct commits to main, and a push to origin/main starts production deployment. Those are precisely the changes that can bypass the restored checks.

This is not a team-governance argument. For a sole owner, a post-push check on main is a cheap alarm even when you intentionally skip a PR.

Recommendation. Trigger the workflow on pushes to main as well. Keep the typecheck explicitly described as scoped. It covers eight selected TypeScript modules, not the whole application.

Changes that held up

The CSV revert was correctly narrow

b202ef01 removed only the 10 MB and 50,000-row gates. It retained strict record parsing, quoted newline handling, full numeric validation, Dutch decimal commas, Amsterdam timestamp interpretation, one parking observation per row, filter disclosure, request cancellation and clean return to live API data.

Assessment: the revert restored your preferred workflow without reviving the earlier semantic and state bugs.

The archive core is proportionate

  • The API key stays in an apikey header and is neither logged nor stored in URLs.
  • Boundary rounding plus the snapshot primary key makes writes idempotent.
  • A transaction commits the snapshot and all positions together.
  • Read API connections are explicitly read-only.
  • Unknown status remains distinct; non-defect is not silently called available.
  • Current four-day Netherlands-wide availability returned in 0.46 seconds.

The September 8 repairs fixed their stated bugs

Account/request ownership includes token, URL, display mode and CSV source. Public defaults no longer overwrite explicit choices. Popup data is built as DOM rather than executable HTML. Selection handlers have stable lifecycles. The Voi frame cache is bounded and its displayed timestamp follows the actual frame.

Assessment: no rollback. The remaining issues are follow-on policy choices, not evidence that this batch should be reverted.

Regional presets and the upstream sync are solid

Regional queries fail closed while any municipality boundary is missing. The live public metadata currently includes all ten priority municipalities, and the plural public zones endpoint works. The CROW sync had one real conflict. The resolution preserved regional ACL checks and upstream's admin exemption, with focused tests.

Assessment: the ordering commit is simple, deterministic, non-mutating and appropriate for your repeated Amersfoort/Gooi workflow.

Recommended order of work

Make freshness and completeness impossible to miss

Add ten-minute index refresh, manual refresh, timestamp/age, and visual gaps. This is the smallest change with the largest monitoring payoff.

Expose the archive you are paying to retain

Add timeline dates and API pagination/windowing. Treat 31 days as a performance question to measure, not a permanent product rule.

Replace the non-defect request fan-out

Use an aggregate series endpoint if possible. Otherwise preserve partial results, surface failures and pin Amsterdam time.

Reconcile the trip histogram with the period selector

Measure actual Voi/region volumes, then aggregate or paginate. Keep good error and cancellation behavior.

Remove misleading operational friction

Redirect the stale Voi guide and run CI after pushes to main.

Schedule the nine-month storage decision

The current 5 GB choice is correct for the plan, but indefinite retention is not. Upgrade, archive, or prune before the volume is close to full; expose capacity monitoring before it becomes urgent.

Small issues to watch, not reasons to detour

Regional fallback is incomplete
The hardcoded municipality fallback includes only Amersfoort, Hilversum and Gooise Meren from the ten priority municipalities. If /public/municipalities fails, all three region presets disappear because access checks correctly fail closed. Since the live endpoint works and individual municipalities still load from the fallback, this is graceful degradation rather than a production blocker.
Area chart retains an old summary while a new area loads
The plot becomes a skeleton, but the header continues to say "Laatste meting" from the previous polygon until the new request completes. Clear or mark the summary as loading if this proves confusing in use.
Voi lasso treats pointer cancellation as completion
pointercancel calls the same handler as pointerup. A browser/OS interruption can therefore finish a partial lasso. The shared map selection tool cancels correctly. This is worth aligning when touching the drawing hook, not as a separate project.
Per-move lasso copies can become expensive
Every pointer move rebuilds GeoJSON from the full accumulated coordinate array. Ordinary hand-drawn areas should be fine, and the server's 5,000-vertex cap is proportionate. Sample or throttle only if real devices show lag.
